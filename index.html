SkyShade

AI Robotics Simulation for an Autonomous Drone Umbrella System

AI in Robotics Project · University of Technology Sydney
Code Wiki Run Results

SkyShade combines perception, flight control, environmental decision-making and navigation safety into a modular ROS2 and PyBullet robotics simulation.

A simulated drone follows a user, monitors environmental conditions, and decides when to deploy or stow an umbrella canopy.

Project Overview

SkyShade is an AI robotics project that models an autonomous drone umbrella system. The aim is to simulate a drone that can detect and follow a user, maintain stable flight, monitor weather conditions, and apply safety decisions during operation.

The project uses PyBullet for simulation and ROS2 for modular communication between subsystems. Instead of building one large script, the system is divided into smaller nodes that represent realistic robotics modules.

The system is designed around four major subsystems: perception, flight control, environmental decision-making, and navigation safety. Each subsystem can be developed and tested separately before being integrated into the full pipeline.

System Architecture

SkyShade is structured as a ROS2 system with four independent nodes. These nodes publish and subscribe to shared topics, allowing each subsystem to communicate without being tightly coupled to the internal code of the others. 

/perception_node        → publishes user position and tracking confidence
/flight_node            → publishes flight command outputs
/env_decision_node      → publishes umbrella deploy/stow commands
/nav_safety_node        → publishes navigation safety overrides

The main ROS2 topics include user position, tracking confidence, flight commands, umbrella commands, battery level, and navigation override. This makes the project easier to debug because each data stream can be inspected directly from the terminal. 

/skyshade/user_position
/skyshade/tracking_confidence
/skyshade/flight_cmd
/skyshade/umbrella_cmd
/skyshade/nav_override
/skyshade/battery_level

Full architecture notes are available in the System Architecture wiki page.

Running the Simulation

The full ROS2 pipeline can be launched from the ROS workspace. The workspace should be built and sourced before running the launch file. 

cd ros2_ws
colcon build --symlink-install
source install/setup.bash
ros2 launch skyshade skyshade_sim.launch.py render:=true

To confirm that the ROS2 system is active, open a second terminal and check the node and topic lists. 

source install/setup.bash
ros2 node list
ros2 topic list
ros2 topic echo /skyshade/umbrella_cmd

The standalone PyBullet simulation can also be run directly when only the visual simulation is needed. 

python3 run_sim.py

More detail is available in the Running the Simulation wiki page.

Subsystems

Sub-1: Perception

The perception subsystem detects the simulated user from the virtual camera feed. It estimates the user's relative position and publishes both position and tracking confidence to ROS2 topics.

The approach uses colour-based marker tracking, distance estimation and smoothing to reduce noisy frame-to-frame movement.

Read the perception wiki page

Sub-2: Flight Control

The flight control subsystem receives the user position estimate and produces flight commands. A PID controller is used at runtime to help the drone follow the user while maintaining a target altitude.

A trained Q-learning policy is kept as an archived model artefact, while the integrated simulation uses the PID controller for stable behaviour.

Read the flight control wiki page

Sub-3: Environmental Decision

The environmental decision subsystem reads simulated weather sensor values such as light, rain and wind. It uses a trained SVM classifier to decide whether the umbrella should be deployed or stowed.

The classifier also uses short-term decision history to reduce rapid switching between states.

Read the environmental decision wiki page

Sub-4: Navigation Safety

The navigation safety subsystem monitors high-level safety conditions such as battery level and distance from home. It can allow normal flight, trigger return-to-home, or request immediate landing.

The policy is generated offline using an MDP and value iteration, then loaded at runtime by the ROS2 node.

Read the navigation safety wiki page

Scenario Gallery

The current simulation includes eleven environments used to test tracking, umbrella deployment, navigation safety and obstacle handling.

Park — open lawn, tightest hover.

Forest — dense objects and mixed terrain.

Building District — urban towers and corridors.

Trail — narrow route following.

Night — low-light tracking conditions.

Rooftop — exposed platform and edge risk.

Beach — open sand and high wind tests.

Parking Lot — vehicle obstacles and lanes.

Vineyard — repeated rows and visibility checks.

Snow — bright ground and cold-weather layout.

Stadium — large open operating space.

Known Issues and Development Decisions

During development, the project required several integration fixes. The subsystem folders were moved into the ROS2 package so that installed ROS nodes could import them correctly. The launch file was also updated so the PyBullet simulation could be started together with the ROS2 nodes.

Other issues included Python package mismatches between Windows virtual environments and Ubuntu/WSL ROS2 Python, missing trained model files, PyBullet GUI behaviour, and GitHub Pages branch setup.

These issues are documented in the Known Issues and Decisions wiki page.
